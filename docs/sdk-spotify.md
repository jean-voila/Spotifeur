# Intégration Spotify de Spotifeur

**App Remote pour la lecture locale déléguée, Web API pour le catalogue et la bibliothèque.** Spotify reste le lecteur sur l’appareil. Spotifeur lui transmet des URI et des commandes, puis observe l’état de lecture. Pour les données de catalogue, Spotifeur appelle la Web API avec l’autorisation de l’utilisateur. Le SDK et la Web API répondent à des besoins différents, même quand ils manipulent la même URI. [Spotify Android SDK](https://developer.spotify.com/documentation/android), [Web API](https://developer.spotify.com/documentation/web-api).

Périmètre vérifié le 3 novembre 2026. Les signatures ci-dessous ont été contrôlées dans les AAR officiels **App Remote 0.8.0** et **Auth 2.1.0**. La matrice indique aussi ce que le reverse engineering de Spotify Android **9.2.0.26** explique lorsque la surface publique est plus étroite. [Publication des AAR](https://github.com/spotify/android-sdk/releases/tag/v0.8.0-appremote_v2.1.0-auth).

| Connexion | App Remote demande `app-remote-control` via son autorisation intégrée. Auth est une bibliothèque séparée de connexion et de consentement. | Pour la Web API, flux Authorization Code avec PKCE, jetons et scopes propres aux fonctionnalités demandées. Spotify indique que la lecture à la demande d’un titre individuel nécessite Premium. Lire `UserApi.getCapabilities().canPlayOnDemand` avant de la proposer. | Le lecteur officiel résout l’URI et ses restrictions. Les métadonnées Web API permettent d’afficher le contexte quand elles sont accessibles. [PlayerApi](https://spotify.github.io/android-sdk/app-remote-lib/docs/com/spotify/android/appremote/api/PlayerApi.html), [UserApi](https://spotify.github.io/android-sdk/app-remote-lib/docs/com/spotify/android/appremote/api/UserApi.html). |

Le modèle SDK expose `isPaused` et six indicateurs de restriction, sans champ `isBuffering` ni diagnostic de qualité. Ces derniers existent dans l’[état interne](audio-natif.md#1-du-contrôle-android-au-moteur). [PlayerApi](https://spotify.github.io/android-sdk/app-remote-lib/docs/com/spotify/android/appremote/api/PlayerApi.html), [ImagesApi](https://spotify.github.io/android-sdk/app-remote-lib/docs/com/spotify/android/appremote/api/ImagesApi.html). |
| Volume et appareil | `ConnectApi` permet de basculer vers l’appareil local, de régler le volume et de s’abonner à son état. | Pour lister et cibler d’autres appareils, la Web API documente les endpoints d’appareils et de transfert avec leurs propres conditions. [ConnectApi](https://spotify.github.io/android-sdk/app-remote-lib/docs/com/spotify/android/appremote/api/ConnectApi.html), [appareils](https://developer.spotify.com/documentation/web-api/reference/get-a-users-available-devices), [transfert](https://developer.spotify.com/documentation/web-api/reference/transfer-a-users-playback). |
| File d’attente | `queue(uri)` ajoute un élément. L’AAR ne fournit pas de lecture de la file complète, de retrait ciblé ni de réordonnancement. | `GET /me/player/queue` donne une vue de la file avec `user-read-playback-state`. Aucun endpoint public de retrait ou de réordonnancement de la file n’a été identifié dans la référence Player. Les opérations existent dans le client officiel et ont été vérifiées dans l’[APK](audio-natif.md#file-dattente-et-téléchargements). [Lecture de la file](https://developer.spotify.com/documentation/web-api/reference/get-queue), [ajout](https://developer.spotify.com/documentation/web-api/reference/add-to-queue). |

| Titres, artistes, albums | Le SDK fournit les métadonnées liées à la lecture et les éléments de ses vues de contenu. | Web API pour les fiches, la discographie et les titres d’album. L’[analyse du catalogue](catalogue.md) établit les modèles internes, la fiche titre, l’onglet À propos et une vue artiste liée à la collection. Le trajet réseau de chaque vue éditoriale album ou artiste reste partiel. Pour une même action, choisir un seul canal et actualiser la vue concernée après succès. L’APK documente la pagination et les deltas internes de Collection v2. [Mise à jour des éléments](https://developer.spotify.com/documentation/web-api/reference/reorder-or-replace-playlists-items), [scopes](https://developer.spotify.com/documentation/web-api/concepts/scopes), [Playlist4](catalogue.md#playlists). |
| Playlists communautaires | Une URI de playlist peut être transmise à `play(uri)`. Afficher les métadonnées accessibles et un lien vers Spotify dans ce cas. Le service de permissions repéré dans l’APK explique les contrôles internes, avec accès serveur tiers non établi. [Get Playlist Items](https://developer.spotify.com/documentation/web-api/reference/get-playlists-items), [liens Android](https://developer.spotify.com/documentation/android/tutorials/content-linking), [permissions internes](catalogue.md#permissions-et-dossiers-de-playlists). |

[Web API](https://developer.spotify.com/documentation/web-api), [analyse des dossiers](catalogue.md#permissions-et-dossiers-de-playlists). |
| Hors-ligne | Spotify peut jouer du contenu qu’il a déjà téléchargé. Le SDK ne programme ni ne supprime les téléchargements et n’expose pas leur progression ou leur licence. | L’[APK](audio-natif.md#file-dattente-et-téléchargements) expose le service interne de téléchargements et les états de licence. Pour une première autorisation, prévoir du réseau. Le tutoriel indique que l’autorisation intégrée peut fonctionner hors-ligne après une connexion réussie dans les dernières 24 h avec les mêmes paramètres. Le README du SDK avertit que le démarrage de la communication requiert du réseau. Ce cas doit être vérifié sur appareil avant d’en faire une promesse. [Tutoriel Android](https://developer.spotify.com/documentation/android/tutorials/getting-started), [README App Remote](https://github.com/spotify/android-sdk/blob/master/app-remote-lib/README.md). |
| Flux audio, codecs, qualité, cache | Le moteur Spotify gère la livraison et la sortie. App Remote n’expose ni octets audio ni clé de flux. `getCrossfadeState` lit l’état du crossfade sans le modifier. | Les mécanismes de résolution, plages CDN, préchargement et décodage sont documentés dans l’[analyse native](audio-natif.md). Le contrat exact de demande de clé, les valeurs négociées et leur acceptation côté serveur restent non validés. Le Web Playback SDK est destiné au navigateur. ### Intégration à retenir

1. Enregistrer le Client ID, le package Android, l’empreinte SHA-1 des certificats de signature et les URI de retour prévues. Configurer l’autorisation intégrée d’App Remote pour la lecture et le flux PKCE pour les scopes Web API. Auth 2.1.0 peut servir à un flux de connexion explicite si nécessaire. Une connexion App Remote réussie n’accorde pas les scopes Web API. [Démarrage Android](https://developer.spotify.com/documentation/android/tutorials/getting-started), [empreintes](https://developer.spotify.com/documentation/android/tutorials/application-fingerprints), [URI de retour](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri).
2. Garder une seule connexion App Remote pour les écrans visibles, s’abonner à l’état et au contexte, puis se déconnecter lorsque l’interface passe en arrière-plan. Reprendre l’état depuis Spotify après reconnexion. Utiliser les restrictions du lecteur et les erreurs réelles pour activer les commandes. La lecture, les notifications système et le focus audio appartiennent à Spotify. [Cycle de vie App Remote](https://developer.spotify.com/documentation/android/tutorials/application-lifecycle).
3. Utiliser les URI Spotify comme lien entre les résultats Web API et le lecteur. Pour sélectionner un titre au sein d’un album ou d’une playlist, conserver son index dans le contexte d’origine, même si l’UI filtre des éléments. Pour une playlist tierce dont les titres sont indisponibles, distinguer « Lire dans Spotify » de « Afficher les titres ». [PlayerApi](https://spotify.github.io/android-sdk/app-remote-lib/docs/com/spotify/android/appremote/api/PlayerApi.html), [Get Playlist Items](https://developer.spotify.com/documentation/web-api/reference/get-playlists-items).
4. Traiter le SDK et le catalogue comme deux états distincts. Une indisponibilité du catalogue ne suffit pas à déclarer le lecteur déconnecté. Une erreur de lecture ne suffit pas à invalider le jeton Web API. Les limites de compte, de quota et d’autorisation sont détaillées dans la [note sur la session](session-et-acces.md#interfaces-officielles-et-conditions-daccès).

La [validation sur le Pixel](validation-pixel.md) a confirmé le démarrage d’un titre du catalogue, la lecture d’une playlist tierce, la lecture d’un album déjà téléchargé en mode hors connexion, la transition naturelle et la tenue du tampon de Spotify pendant une perte de réseau. Avec App Remote, Spotifeur hérite de ce tampon d’environ 11 min à 160 kbit/s : l’indicateur de chargement doit suivre l’état `BUFFERING` publié par Spotify plutôt que la connectivité Android. La connexion App Remote, la réponse Web API pour la même playlist et la reconnexion hors ligne d’une application tierce restent à vérifier avec un Client ID enregistré et ses autorisations.

### Reproduire la vérification des AAR

Télécharger les deux AAR de la [version vérifiée](https://github.com/spotify/android-sdk/releases/tag/v0.8.0-appremote_v2.1.0-auth) et extraire `classes.jar` avec `unzip -p`. Utiliser `javap -classpath <classes.jar> <nom-de-classe>` sur les interfaces `com.spotify.android.appremote.api.PlayerApi`, `UserApi`, `ImagesApi`, `ContentApi`, `ConnectApi` et sur `com.spotify.sdk.android.auth.AuthorizationClient` dans l’AAR Auth.

- App Remote 0.8.0 SHA-256 `b5a6dd880eaf01f63a871cba9ef7af77c341f8a94ffc8fdf2e9021f9a9d4c198`.
- Auth 2.1.0 SHA-256 `2a0710699c79cd0238b3b14e2cd9e34f15321806414541b0fc6c961a4a2d9a9c`.
